# Estonian ASR Workbench — results site

A separate, static, read-only frontend for the [Estonian ASR
Workbench](../estonian-asr-workbench). It reads only precomputed data from
`site-data/` — plain HTML/CSS/JS, no build step, no framework, no backend.

**Current status:** all five priority routes are live — Home, Compare,
Transcripts, Systems, Methodology. `Findings`, `Privacy`, and `About` are
not built yet.

## Hard constraints (see the Workbench's approved site proposal)

- No live transcription, no audio upload, no backend, no API routes, no database.
- No credentials, audio, model weights, or local filesystem paths in this repo.
- All word-level alignment (match/substitution/deletion/insertion/boundary)
  is precomputed in Python by the Workbench's own canonical scoring code —
  this frontend only renders `site-data/alignments/*.json`, never
  recomputes scoring or alignment in JavaScript.

## Running locally

Any static file server works, e.g.:

```bash
python3 -m http.server 8000
# then open http://localhost:8000/
```

Opening the HTML files directly via `file://` will NOT work — the pages
`fetch()` JSON from `site-data/`, which requires an HTTP origin.

## Regenerating site-data/

`site-data/` is a vendored, versioned snapshot — never generated by this
repo itself. To refresh it:

```bash
cd ../estonian-asr-workbench
python3 tools/export_site_data.py       # writes ./site-data/
# review the output, then:
rm -rf ../estonian-asr-workbench-site/site-data
cp -r site-data ../estonian-asr-workbench-site/site-data
```

`site-data/manifest.json` records the export timestamp, Workbench version,
methodology version, source commit (if the Workbench repo has one), and
system/set counts — check it after copying to confirm what you're looking at.

## Layout

```
index.html           Home
compare.html          Filterable comparison table, per-set breakdown
transcripts.html      Set + 2-4 system picker, diff-highlighted comparison
systems.html           System catalog -- grouped by category, expandable profiles
methodology.html       Plain-language summary, then full technical detail
css/style.css         Shared styles (light/dark via prefers-color-scheme)
js/data.js             Shared data loading, header/footer chrome, and the
                        factual-dimension label helpers (deploymentBadge,
                        hardwareLabel, reproLabel, streamingLabel, tunedLabel,
                        esc) that /compare and /systems both use -- defined
                        once so the two pages can't silently disagree.
js/{home,compare,transcripts,systems,methodology}.js   Per-page logic
site-data/              Vendored export (see above)
```
